# Policy: IAM Restrictions — No Wildcards

## Scope
All IAM roles, policies, and policy attachments generated by the agent.

## Hard Rules

### 1. No Action Wildcards
NEVER generate an IAM policy with `Action = "*"`.
Use the minimum required action set for the stated use case.

**Forbidden:**
```json
{
  "Effect": "Allow",
  "Action": "*",
  "Resource": "*"
}
```

### 2. No Resource Wildcards Without Justification
Avoid `Resource = "*"` wherever a specific ARN or ARN pattern is possible.
Acceptable only for actions that genuinely require it (e.g., `ec2:DescribeVpcs`).

### 3. No Privilege Escalation Patterns
Do NOT combine the following permissions in the same policy without explicit user request:
- `iam:PassRole` + `lambda:CreateFunction` (can escalate to any role the passer can pass)
- `iam:CreatePolicyVersion` + `iam:SetDefaultPolicyVersion` (policy replacement escalation)
- `iam:CreateLoginProfile` + `iam:UpdateLoginProfile` (console takeover)

If the user's request genuinely requires one of these, include a comment explaining why,
and flag it in the Change Summary.

### 4. Principle of Least Privilege
Scope IAM policies to the specific resources created within this job:

```hcl
resource "aws_iam_role_policy" "this" {
  role = aws_iam_role.this.id
  policy = jsonencode({
    Version = "2012-10-17"
    Statement = [{
      Effect   = "Allow"
      Action   = ["s3:GetObject", "s3:PutObject"]
      Resource = "${aws_s3_bucket.this.arn}/*"  # scoped to this bucket only
    }]
  })
}
```

## Enforcement

The Blast-Radius Guard (Phase 3.5) scans all IAM policy documents in the real `terraform plan`
JSON output for wildcard patterns before any human reviewer sees the plan.
A violation is a hard-block on apply, regardless of trust score.
